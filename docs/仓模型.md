# 仓模型与事实口径

`mealwh` 分三层：入仓层、事实层、结算层。本文说明各层结构与业务口径的落点；来源字段含义以 docs/资料口径.md 为准。

## 入仓层(持续入仓)

- `receive_batch`：一次接收为一个批次，批次号与接收时刻由调用者明确；接收时刻即该批事实的最早可知时刻(available_at 的角色)，规范为 UTC 文本存储。
- `raw_file`：原始文件全文、摘要、行数随批次保留；同一表内相同文件摘要不再接收，不增加事实。
- `raw_row`：逐行版本。同一记录键的新行表示整行修订，旧版本保留；相同内容的行不重复入仓。业务时点(如 effective、at)与接收时点分开存放。

历史截点构建只使用截点时已接收的批次，晚知的值不进历史截点。

## 事实层(多粒度事实)

`build` 是一次事实构建，固化以下事实表；历史构建不改动。

- `fact_slot` 槽位：订餐变更按 effective 排序成时间线，取餐次时点生效的状态(餐种/病区/active/cancelled)。修订沿原槽位延续，不增餐。无变更证据时状态记 `unknown`。
- `fact_portion` 餐份：送出、病区签收、本人领取、废弃分层记录。同一份餐凭 portion_id 只算一次服务；served 只认可本人回执(当前资料无代理关系表，代领取须有明确代理关系才认可)；单病区收餐不证明个人吃到。同一餐份出现多个病区回执记 `ward_conflict` 待核实；旧病区补签不变成第二份交付。`ward_at_sent` 保留送出时归属，`service_ward` 取餐次时点病区为最终服务归属。
- `fact_product` 锅次产出：制作份数与送出份数分开，制作未送出(made_not_sent)是独立损耗原因，含职工份。
- `fact_pot` 锅次汇总：制作/送出/领取/送出未领/废弃/制作未送分列，不从制作量里净扣成净餐数；成本按患者/职工用途汇总。
- `fact_pot_ingredient` 锅次食材：实耗=领-退(余料退回可再用)；成品退餐只记废弃，不恢复原料库存。保留实耗与标准配方(产出份数×配方克数)的差额 variance。
- `fact_alloc` 共锅分摊：实耗成本按该锅实际产出的各餐种标准原料权重(份数×配方克)分担，分母包括已制作未送出份与职工份，不只让已领餐人员承担。金额舍入到分，尾差归分摊基数最大项，并列按业务键升序。
- `fact_fee` 费用资格：槽位在餐次时点为取消时，取消时点晚于该槽位送出份对应锅次的 cutoff_at 仍收内部服务费(每份 20 元)；无送出份或缺锅次记录时截止时点未决。费用资格与实际供餐分离，费用资格不覆盖实际供餐。

缺锅次或缺领退证据时，供餐事实(送出、签收、领取)仍可确认，食材成本标记 `pending` 未决并给出原因(缺锅次记录/缺领退证据/缺锅次产出记录/缺配方或配方权重为零)。

## 结算层(只增不改)

`settle` 对某一构建做结算确认：`settlement_fee` 固化全部槽位的费用资格行，`settlement_cost` 固化各锅次用途分摊行；未决的锅次食材同样入结算并标明未决，不留白。结算后到达的转科补录、原料退库经新批次入仓、新构建、新结算反映；原结算行不改动，`settlement --id A --compare B` 按业务键对齐比较两次结算的依据差异。

## 查询视角

- `fulfillment`：按餐次×病区。需求取餐次时点 active 的槽位；送出/领取/送出未领/废弃按最终服务归属(餐次时点病区)归集；费用资格单列。制作未送出份不按病区归集，在锅次查询中按用途列示。
- `pot-cost`：按锅次。产出核对、领退与实耗、标准差额、各用途成本与未决原因。
- `trace`：从患者餐记录(槽位或餐份)回溯对应锅次、制作与收费截止时点、回执链与费用资格。
